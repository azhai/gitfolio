# 仓库存储、项目类型与权限

## 一、仓库存放在哪里

仓库的落盘位置由**所有者（用户或团队）是否设置了自有仓库目录**决定，与项目类型无关。

| 条件 | 落盘路径 | 存储形态 |
|------|----------|----------|
| 账号设置了 `repo_root` | `<repo_root>/<仓库名>` | 普通仓库（带工作区，含 `.git`） |
| 未设置 `repo_root` | `<REPO_ROOT>/<账号名>/<仓库名>.git` | 裸仓库（无工作区） |

- `repo_root` 是 `user` 表与 `group` 表的字段，在个人设置 / 新建团队时填写，留空表示使用全局裸仓库目录。
- `REPO_ROOT` 来自环境变量 `REPO_ROOT`（默认 `./repos`），是全局裸仓库根目录。
- 账号名与仓库名会被规整为安全目录名（只保留字母、数字、`.`、`_`、`-`），含 `..` 的自有目录会被拒绝并回退到裸仓库布局。
- 仓库记录在 `repository.local_path` 中保存实际路径；该字段为权威值。

仓库位置只有这两个来源，没有第三个兜底目录：`LOCAL_ROOT` 配置项已移除。

### 迁移

启动时 `models.MigrateOrphanRepositories` 会：

1. 把 `owner_id = 0` 的仓库（旧代码创建本地项目时清空了归属）挂到第一个管理员账号；
2. 为 `local_path` 为空的仓库按上面的规则回填路径。

已经在磁盘上的老仓库不会丢：其 `local_path` 已被记录，运行时优先使用该值。

## 二、项目类型

`project_type` 描述仓库**与远程平台的关系以及可见性**，与磁盘形态无关：

| 类型 | 含义 | 可推送远程 |
|------|------|-----------|
| `local` | 本地自有项目，不做平台同步（可自行 `git remote` 推送） | 是 |
| `mirror` | 远程平台的只读镜像，定期从 `mirror_url` 拉取 | 否 |
| `public` | 已推送到远程平台并同步议题/PR，所有人可见 | 是 |
| `private` | 同上，仅所有者、团队成员、管理员可见 | 是 |

注意：镜像仓库若落在自有目录下同样是普通仓库，可以在网页上编辑——能否编辑取决于存储形态（`has_work_tree`），不取决于项目类型。

## 三、权限

系统角色：`admin`（站长）、`user`、`guest`。

团队角色（`group_member.role`）：`owner` / `admin` / `leader`（历史值，等同 `admin`）/ `member`。团队创建者（`group.owner_id`）即使没有成员记录也视为管理员。

仓库权限级别（`helpers.CheckRepoAccess`）：

| 级别 | 说明 | 授予对象 |
|------|------|----------|
| `Admin` | 删除、转移、改设置、管理同步 | 站长、仓库所有者、团队管理员 |
| `Write` | 提交代码、修改议题 | 同 Admin（当前实现合并） |
| `Read` | 浏览代码、议题、PR | 私有项目的团队成员；公开项目的登录用户 |
| `None` | 不可见 | 游客；非成员的私有项目；未登录访问本地项目 |

判定顺序：站长 → 游客拒绝 → 所有者 → 本地项目需登录 → 私有项目需团队成员 → 其余登录用户可读。

迁移前遗留的无归属仓库（未跑迁移时 `owner_id = 0`）：登录用户按所有者处理，便于管理员后续转移。
